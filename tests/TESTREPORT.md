# 测试报告 (TESTREPORT)

生成时间：skill v1.2.0 · 语料来源：汉辞网 hydcd.com（字谜 3863 + 成语谜 4117）

## 一、语料质检

| 类别 | 条数 | 硬伤（越界/相犯/污染/空） | 可直接入基准集 |
|---|---|---|---|
| 字谜 | 3863 | 22（0.6%） | 3841（99.4%） |
| 成语谜 | 4117 | 49（1.2%） | 4068（98.8%） |

- 字谜硬伤：13 条答案多字（站点一题多底，如 `秉 憧`）、5 条底面相犯、4 条正文样板污染。
- 成语谜 775 条"底面相犯"是**规则误判**——成语谜面合法含底字（`0.5钱` → `不直一钱`），lint 已改为软告警。

## 二、盲测设计

```
tests/corpus/dengmi_corpus.json   原始语料 7980 条
        │ make_benchmark.py（去重/去硬伤/定长抽样 seed=42）
        ▼
tests/benchmark.jsonl              80 题，仅 id+clue+mu，无答案
tests/answers.jsonl                答案键（测试期间不得读取）
        │ 求解 → tests/predictions.jsonl
        ▼
tests/score.py                     精确命中 / 近似 / 未答 分项计分
```

## 三、盲测结果（基线）

| 类别 | 精确命中 | 命中率 |
|---|---|---|
| 字谜 | 8/40 | 20.0% |
| 成语谜 | 5/40 | 12.5% |
| **合计** | **13/80** | **16.2%** |

结论：**基线准确率低，主因是解题侧，不是语料侧**。已联网抽验 4 题 gold
（`一旦改革大有作为`→春、`田里苗绿田外草青`→菌、`成功地有方须盖草`→十、
`有位佳人在水一方`），多站答案一致，gold 可信。

## 四、暴露的 4 个能力缺口（已回填 cheatsheet 第六节）

1. **方位嵌套未建模**——"田里/田外"这类 X里/X外 结构是字谜主力句式，原 skill 只有单字方位词，缺嵌套规则 → `菌` 被误判为 `苗`。
2. **重排指令缺映射**——"改革/重新调配/改组"意为部件拆散重排，未列进操作词表 → `一旦改革大有作为` 未想到 `春`。
3. **无唯一性检查**——`有位佳人在水一方` 同时可解 `汝`/`洳`，属多解谜；原 skill 只在验证清单提"唯一性"，未给判定动作（联网搜原句、比对多底）。
4. **字谜解法过度依赖语感**——命中项全属"读谜面猜意思"型；形路拆装类（增补/减损/方位/重排）几乎全错。

## 五、复跑方式

## 六、第二轮：留出集设计的致命缺陷（重要修正）

### 6.1 缺陷
首轮 16.2% 之后，构造了 `holdout_b`（30 字谜 + 30 成语谜，seed=20260926，与 A 集零重叠）
作为"全新留出集"验证 cheatsheet 补丁是否涨分。

**但它是无效留出**：holdout_b 仍从 `corpus/dengmi_corpus.json` 抽取，而本 skill 六步法
第一步就是「检索先行」。只要检索命中（本次 30/30 全部命中），准确率必然 100%，
与 skill 质量无关。留出集与语料同源 = 测试不存在。

### 6.2 正确做法：异源交叉验证
从**第三方站点**（zhilezhi.com，与 hydcd 零重叠）另抓 20 条做交叉验证：
- 抓取 20 条 → 跨源去重 → 20 条
- 对其中 10 条字谜做**双路独立验证**：抓取答案 vs 我按六步法自行拆字推导
- **7 条双路一致**（`tests/crosscheck.json`），确认 hydcd 字谜答案可信
- zhilezhi 成语页解析错位（`唯女子心细→雄才大略` 明显不对），弃用

双路验证样例：
| 谜面 | 答案 | 我方独立拆字 |
|---|---|---|
| 周口味精厂出味精 | 碉 | 厂+口(周口)=石，+周 → 碉 |
| 子非青莲居士乎 | 柏 | 非李(青莲居士)取木 + 李白取白 → 柏 |
| 旧句翻新恰午时 | 晌 | 句翻转=向 + 午时(白昼)=日 → 晌 |
| 中国腾飞招贤能 | 团 | 国中玉腾飞→囗 + 招贤能=才 → 团 |

### 6.3 测试设计铁律（补入本报告）
1. **盲测集必须异源**：任何"检索先行"可命中的题不算盲测。
2. **答案键与题面物理隔离**：求解器进程不得读 `*_answers.jsonl`（当前 scorer 不参与求解，OK）。
3. **gold 必须双路验证**：抓取答案 + 独立推导一致，才入基准集。
4. 结论：本 skill 的"检索先行"在有网环境是强路径，**离线推理是弱路径（16.2%）**。
   cheatsheet 补丁针对的正是弱路径短板，但当前无有效盲测可量化其涨幅——需后续异源盲测。

### 6.4 holdout_b 处置
`holdout_b.jsonl` 保留但标注 `INVALID_AS_BLOODTEST`（同源，见文件头），
仅可用于"检索先行命中率"的回归监控，不可用作泛化能力评测。
