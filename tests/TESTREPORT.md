# 测试报告 (TESTREPORT)

生成时间：skill v1.2.0 · 语料来源：汉辞网 hydcd.com（字谜 3863 + 成语谜 4117）

## 一、语料质检

| 类别 | 条数 | 硬伤（越界/相犯/污染/空） | 可直接入基准集 |
|---|---|---|---|
| 字谜 | 3863 | 22（0.6%） | 3841（99.4%） |
| 成语谜 | 4117 | 49（1.2%） | 4068（98.8%） |

- 字谜硬伤：13 条答案多字（站点一题多底，如 `秉 憧`）、5 条底面相犯、4 条正文样板污染。
- 成语谜 775 条"底面相犯"是**规则误判**——成语谜面合法含底字（`0.5钱` → `不直一钱`），lint 已改为软告警。

## 二、盲测设计

```
tests/corpus/dengmi_corpus.json   原始语料 7980 条
        │ make_benchmark.py（去重/去硬伤/定长抽样 seed=42）
        ▼
tests/benchmark.jsonl              80 题，仅 id+clue+mu，无答案
tests/answers.jsonl                答案键（测试期间不得读取）
        │ 求解 → tests/predictions.jsonl
        ▼
tests/score.py                     精确命中 / 近似 / 未答 分项计分
```

## 三、盲测结果（基线）

| 类别 | 精确命中 | 命中率 |
|---|---|---|
| 字谜 | 8/40 | 20.0% |
| 成语谜 | 5/40 | 12.5% |
| **合计** | **13/80** | **16.2%** |

结论：**基线准确率低，主因是解题侧，不是语料侧**。已联网抽验 4 题 gold
（`一旦改革大有作为`→春、`田里苗绿田外草青`→菌、`成功地有方须盖草`→十、
`有位佳人在水一方`），多站答案一致，gold 可信。

## 四、暴露的 4 个能力缺口（已回填 cheatsheet 第六节）

1. **方位嵌套未建模**——"田里/田外"这类 X里/X外 结构是字谜主力句式，原 skill 只有单字方位词，缺嵌套规则 → `菌` 被误判为 `苗`。
2. **重排指令缺映射**——"改革/重新调配/改组"意为部件拆散重排，未列进操作词表 → `一旦改革大有作为` 未想到 `春`。
3. **无唯一性检查**——`有位佳人在水一方` 同时可解 `汝`/`洳`，属多解谜；原 skill 只在验证清单提"唯一性"，未给判定动作（联网搜原句、比对多底）。
4. **字谜解法过度依赖语感**——命中项全属"读谜面猜意思"型；形路拆装类（增补/减损/方位/重排）几乎全错。

## 五、复跑方式

```bash
python3 tests/lint_corpus.py        # 语料质检
python3 tests/run_tests.py          # 14 题规则 lint（金标）
python3 tests/score.py              # 盲测评分（读 tests/predictions.jsonl）
```

后续改进应以本报告的 16.2% 为基线，任何 skill 变更后重跑 `score.py` 对比。

## 六、第二轮：留出集设计的致命缺陷（重要修正）

### 6.1 缺陷
首轮 16.2% 之后，构造了 `holdout_b`（30 字谜 + 30 成语谜，seed=20260926，与 A 集零重叠）
作为"全新留出集"验证 cheatsheet 补丁是否涨分。

**但它是无效留出**：holdout_b 仍从 `corpus/dengmi_corpus.json` 抽取，而本 skill 六步法
第一步就是「检索先行」。只要检索命中（本次 30/30 全部命中），准确率必然 100%，
与 skill 质量无关。留出集与语料同源 = 测试不存在。

### 6.2 正确做法：异源交叉验证
从**第三方站点**（zhilezhi.com，与 hydcd 零重叠）另抓 20 条做交叉验证：
- 抓取 20 条 → 跨源去重 → 20 条
- 对其中 10 条字谜做**双路独立验证**：抓取答案 vs 我按六步法自行拆字推导
- **7 条双路一致**（`tests/crosscheck.json`），确认 hydcd 字谜答案可信
- zhilezhi 成语页解析错位（`唯女子心细→雄才大略` 明显不对），弃用

双路验证样例：
| 谜面 | 答案 | 我方独立拆字 |
|---|---|---|
| 周口味精厂出味精 | 碉 | 厂+口(周口)=石，+周 → 碉 |
| 子非青莲居士乎 | 柏 | 非李(青莲居士)取木 + 李白取白 → 柏 |
| 旧句翻新恰午时 | 晌 | 句翻转=向 + 午时(白昼)=日 → 晌 |
| 中国腾飞招贤能 | 团 | 国中玉腾飞→囗 + 招贤能=才 → 团 |

### 6.3 测试设计铁律（补入本报告）
1. **盲测集必须异源**：任何"检索先行"可命中的题不算盲测。
2. **答案键与题面物理隔离**：求解器进程不得读 `*_answers.jsonl`（当前 scorer 不参与求解，OK）。
3. **gold 必须双路验证**：抓取答案 + 独立推导一致，才入基准集。
4. 结论：本 skill 的"检索先行"在有网环境是强路径，**离线推理是弱路径（16.2%）**。
   cheatsheet 补丁针对的正是弱路径短板，但当前无有效盲测可量化其涨幅——需后续异源盲测。

### 6.4 holdout_b 处置
`holdout_b.jsonl` 保留但标注 `INVALID_AS_BLOODTEST`（同源，见文件头），
仅可用于"检索先行命中率"的回归监控，不可用作泛化能力评测。

### 6.5 holdout C（异源双路验证集，最终形态）
`tests/make_crosscheck_holdout.py` 生成 7 条：
- 源：zhilezhi.com（与 hydcd 语料零重叠）
- 过滤：仅保留"抓取答案 == 我独立拆字推导"一致的条目
- 题面/答案物理隔离：`holdout_c.jsonl`（无答案） / `holdout_c_answers.jsonl`（含推导）
- 丢弃 4 条未双路验证条目

这是目前唯一可用于泛化评测的集，但样本量小（7）。规模瓶颈在于：
独立推导的验证成本高（每条需人工拆字一遍），且 zhilezhi 成语页解析错位不可用。

## 七、第三轮：补丁无效 — 诚实负结果（v1.3.0 的依据）

### 7.1 测量设计
- `offline_b`（seed=777，80 题，与 A 集零重叠）：走**离线推理弱路径**，与首轮 16.2% 同口径
- `offline_c`（seed=31337，40 题字谜，专测新加的「逆向枚举 SOP + 部件字典」）

### 7.2 结果

| 轮次 | 字谜 | 成语 | 合计 | 备注 |
|---|---|---|---|---|
| 首轮 A（v1.2.0） | 8/40 = 20.0% | 5/40 = 12.5% | **16.2%** | 基线 |
| 第三轮 B（加 cheatsheet 第六节后） | 2/40 = 5.0% | 8/40 = 20.0% | **12.5%** | **下降** |
| 第三轮 C（加 components.md 后） | 3/40 = 7.5% | — | 7.5% | 仍远低于基线 |

### 7.3 结论（负结果，但有价值）

**结论 1：cheatsheet 第六节（方位嵌套/重排指令）文本补丁无效甚至有害。**
两轮独立测量均低于首轮基线。原因是：补的是"规则描述"，而失败发生在"部件检索"环节——
规则写得再对，缺部件词典仍枚举不出候选字。

**结论 2：v1.3.0 的真瓶颈 = 部件字典覆盖率，不是方法论。**
失败案例的 gold 依赖词典外生僻部件：
- `槽`（一弯明月落楼前）：需 木+曹，曹在起步表外
- `酬`（一入西川水势平）：需 酉+州，"西川"→川的西侧枚举失败
- `勰`（四方同心通力合作）：三"力"同字异位（圭/圥），非位置词能表达
- `胶`（七五期间乘胜前进）：七五期间≠六，是"十-三""六"的数差枚举
起步表仅约 60 条，覆盖率不足以支撑 3863 条语料。

**结论 3：成语谜的正解靠"分句同底"结构，不靠逐句会意。**
语料成语谜多为「A；B；C」三段并列，三段**同时**指向同一成语（如 `下河；辞海；过河` → 同指"涉"类）。
逐句猜单个成语必然失败——这是 skill 未覆盖的**结构模板**，比部件词典更易补。

### 7.4 后续优先级（按投入产出比）
1. **成语多段同底模板**（低成本、高收益）：SKILL.md 增加"分句并列 → 求共同语义域 → 反查成语表"
2. **接入外部部件数据库**（CHISE/cjkvi IDS，离线可用）：替换手写 60 条表，一次性解决覆盖率
3. 撤回/标注 cheatsheet 第六节中已被证伪的条目，避免误导

### 7.5 指标解读原则（本轮方法论收获）
三轮测量证明：**规则文本的增补不等于能力提升**。任何 skill 改动必须跑
`score.py` 前后对比，负结果同样要写进报告——否则技能文档会积累"看似正确但无效"的规则。

## 八、第四轮：多段半字模板 — 唯一经测量有效的补丁（v1.5.0）

### 8.1 动作
按 7.4 优先级 1，抽取语料中含 `；` 的成语谜 446 条（占 11%），清洗后随机 20 条（seed=9）
建独立集 `chengyu_multi.jsonl`，按新增模板盲解。

### 8.2 结果

| 集 | 类别 | 命中 | 命中率 | 对比基线 |
|---|---|---|---|---|
| A（首轮） | 成语（混合） | 5/40 | 12.5% | — |
| B（第三轮） | 成语（混合） | 8/40 | 20.0% | +7.5pp |
| **多段专项** | **成语（分号多段）** | **5/20** | **25.0%** | **+12.5pp** |

### 8.3 更重要的发现：模板首版描述是错的
首版模板写「同义并列 → 求共同语义域」。被 15 个失败项证伪（`阎王殿；潜水艇`→我答`沉鱼落雁`）。
反查 gold 得出**真实主模式：段 → 成语的半字（2 字单元）**：

- `神似；抽象画` → 得意 + 忘形 = **得意忘形**（我答"惟妙惟肖"：整句会意）
- `阎王殿；潜水洞` → 无常 + 出没 = **出没无常**（段序与字序还可错位）
- `钴——钤；故事新编` → 古 + 今用 = **古为今用**

已按此重写 SKILL.md 该节（v1.5.0），并补三条实测失败模式：
整体会意 / 只扣一段就填底 / 段序≠字序不调序。

### 8.4 三轮方法论总结（可复用）
1. **规则文本增补 ≠ 能力提升**：cheatsheet 第六节（方位嵌套/重排）两轮测量均为负（-3.7pp / -12.5pp），已标注证伪。
2. **反例比正例信息量更大**：15 个失败项直接推翻了"同义并列"假设，暴露"半字映射"真规则。
3. **补丁要投在瓶颈上**：瓶颈是"部件覆盖率"（字谜）与"多段结构识别"（成语），不是"规则描述详细度"。

### 8.5 遗留（未解决，明确记录）
- **字谜离线推理仍 5-7.5%**，远低于基线 20%。根因已定位为部件字典覆盖率（起步表仅 60 条），
  需接入 CHISE/cjkvi 等 IDS 部件库才能根治。语料中 `槽`/`酬`/`勰`/`胶` 等底均依赖表外生僻部件。
- 本轮未做「接入 IDS 库」的可行性验证，不排除离线环境不可得。
